# 接口确认清单（发给 IT / 自研项目系统负责人）

目标是先打通**只读、按项目范围、可审计**的最小集成。请勿一开始申请全量邮件、全量钉钉或生产写权限。

## 一、自研项目管理系统（最高优先级）

### 需要确认

1. 是否有 REST API、GraphQL API、数据库只读视图、导出接口或 Webhook？
2. 如何按 `project_id` 查询项目、里程碑、任务、风险和附件？
3. Timeline 是否包含：计划/实际日期、状态、负责人、依赖关系、关键路径、版本号、最后更新时间？
4. 如何区分“已批准基线”“草稿计划”“已废弃版本”？
5. 是否提供增量同步字段（`updated_at`、版本号、变更日志）？
6. API 是否支持按服务账号、项目权限和只读 scope 授权？
7. 是否有测试环境/测试项目？
8. 未来写回时，是否支持幂等键、ETag/版本校验、审计 ID 和回滚？

### 最小只读接口（示意，不是假定现有接口）

```text
GET project by project_id
GET milestones/tasks by project_id
GET project changes since cursor
GET document metadata by project_id
```

## 二、阿里企业邮箱（客户沟通）

### 需要确认

1. 公司邮箱采用何种连接方式：IMAP/SMTP、Exchange 协议、企业 API、网关或归档系统？
2. 是否允许服务账号或 OAuth 授权的**只读**邮件访问？
3. 是否能限定访问 PM 指定邮箱文件夹、项目标签或项目编号过滤？
4. 是否可读取 message ID、thread ID、收件人、时间、主题、正文和附件元数据？
5. 附件是否有大小、类型、保密或下载限制？
6. 是否可以只创建草稿而不发送？若不可以，Harness 仅输出 Markdown/HTML 草稿。
7. 邮件保留、审计、导出和客户数据脱敏规则是什么？

### 最小只读范围

```text
指定 PM 邮箱或共享项目邮箱
+ 项目编号 / 客户域名过滤
+ 收发件元数据、正文摘要、附件元数据
```

## 三、钉钉（内部协作）

### 需要确认

1. 是否有已登记的企业内部应用？其权限管理员是谁？
2. 是否可按项目群、群 ID、项目编号或部门范围读取消息/会议/待办元数据？
3. 是否能获取消息 ID、发送人、时间、会话/群 ID、消息内容或摘要、附件元数据？
4. 是否有会议纪要、日程、任务或待办的 API，且是否与项目编号关联？
5. 可否建立只读 scope 与测试群？
6. 后续发消息、建待办、创建日程需要哪些权限、审批和审计？

### 最小只读范围

```text
指定测试项目群
+ 指定时间窗口
+ 消息/会议/待办元数据
+ 不发送消息、不创建待办
```

## 四、安全与验收

- 使用测试项目和虚构客户数据先完成 API 连通性测试。
- 服务账号只授予最小只读 scope，密钥保存在公司指定 Secret Manager。
- 所有同步保存：外部系统 ID、时间、查询范围、响应版本、错误和重试记录。
- 高风险信息（合同、偏差、OOS、CAPA、放行、客户承诺）默认 restricted。
- IT、PM、QA/法务共同确认邮件草稿、Timeline 分析和未来写回的审阅边界。

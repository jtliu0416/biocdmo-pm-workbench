# 企业系统集成方案：阿里企业邮箱 + 钉钉 + 自研项目管理系统

## 系统定位

| 系统 | PM Harness 中的角色 | 数据主责 | 第一阶段权限 |
|---|---|---|---|
| 自研项目管理系统 | 项目事实和 Timeline 的主系统（System of Record） | 项目、里程碑、任务、负责人、计划/实际日期、状态 | 只读 |
| 阿里企业邮箱 | 客户沟通证据和邮件草稿出口 | 客户邮件线程、附件、收发时间、收件人、客户承诺 | 只读检索 + 草稿生成 |
| 钉钉 | 内部协作、会议和催办入口 | 内部讨论、会议通知、任务提醒、审批/待办（如已启用） | 只读检索 + 草稿生成 |
| BioCDMO PM Harness | 跨系统项目控制层，不替代任一业务系统 | 可追溯的项目事实索引、分析、草稿和审计 | 只读优先 |

## 目标架构

```text
                 ┌──────────────────────────────┐
                 │     BioCDMO PM Harness       │
                 │  Facts / Risks / Actions     │
                 │  Drafts / Weekly Control     │
                 └──────────────┬───────────────┘
                                │
       ┌────────────────────────┼────────────────────────┐
       │                        │                        │
┌──────▼───────┐        ┌───────▼────────┐       ┌──────▼───────┐
│ 自研项目系统  │        │ 阿里企业邮箱     │       │ 钉钉          │
│ Timeline主数据│        │ 外部客户沟通证据 │       │ 内部协作证据  │
└──────────────┘        └────────────────┘       └──────────────┘
```

**关键原则：** 自研系统内已批准的 Timeline 是计划日期的唯一主来源；Harness 只对数据做读取、交叉核对、风险提示和草稿生成。除非后续明确设计受控写回，否则 Harness 不更新 Timeline。

## 第一阶段（推荐：只读控制塔）

### A. 自研项目管理系统 / Timeline

读取字段：

- `project_id`、项目名称、客户、分子、阶段、项目经理
- milestone/task ID、名称、计划/实际开始和结束日期、状态、负责人
- 前置依赖、关键路径标记（若系统提供）、最后更新时间、版本号

产生的 Harness 能力：

- `/timeline-check`：延期、At Risk、缺负责人、依赖链和关键路径检查。
- `/weekly-review`：以 Timeline 为主事实来源生成周报。
- 识别客户输入对里程碑的影响，但不篡改计划。

### B. 阿里企业邮箱 / 客户沟通

读取范围建议按：项目编号、客户域名、项目别名、PM 邮箱文件夹或标签进行限定。

读取字段：

- message ID、thread ID、发件人/收件人/抄送、收发时间、主题、正文摘要、附件名
- 项目编号、客户承诺日期、客户待确认事项、会议邀请和附件版本

产生的 Harness 能力：

- 将客户确认、客户待办和外部承诺与 Timeline 对齐。
- 生成客户周报、会议纪要发送邮件和催办邮件**草稿**。
- 标记邮件中与主 Timeline 冲突的日期或未批准承诺。

第一阶段禁止：自动发信、自动移动或删除邮件、自动下载受限附件。

### C. 钉钉 / 内部协作

读取范围建议按：项目群、项目标签、项目编号、指定团队或指定 PM 进行限定。

读取字段：

- 会话/消息 ID、发送人、时间、消息摘要、会议标题/时间、待办/任务引用（如可用）
- 内部行动项、阻塞、资源问题、风险升级建议和会议决议

产生的 Harness 能力：

- 生成内部会议纪要与本周内部跟进清单。
- 将有来源的内部行动项与项目系统 Task/Action 对照，提示重复或漏登。
- 为钉钉项目群生成“待 PM 审阅”的进度提醒草稿。

第一阶段禁止：自动发群消息、自动创建待办、自动发起审批。

## 跨系统事实优先级与冲突规则

| 事实类型 | 主来源 | 其他系统的作用 |
|---|---|---|
| 已批准 Timeline 日期、里程碑状态 | 自研项目管理系统 | 邮件/钉钉仅作为变更线索或补充证据 |
| 客户明确确认、客户请求、客户承诺 | 阿里企业邮箱 | 写入/更新前需 PM 确认 |
| 内部阻塞、资源状态、会议讨论 | 钉钉或内部会议纪要 | 必须标记为内部信息，不应直接面向客户表述 |
| 合同责任和交付义务 | 已批准合同/SOW/质量协议 | 邮件不能覆盖合同条款 |

发现冲突时输出：`Conflict → source A → source B → impact → PM decision needed`，绝不静默选择某一日期。

## 数据映射

| Harness 字段 | 自研项目系统 | 阿里邮箱 | 钉钉 |
|---|---|---|---|
| `project_id` | 主键 | 邮件主题/标签/映射表 | 群名、标签/映射表 |
| `milestone.id` | 里程碑 ID | 引用线索 | 引用线索 |
| `milestone.planned_date` | 主数据 | 仅核对 | 仅核对 |
| `action.id` | 任务/待办 ID（如有） | 邮件行动项线索 | 钉钉待办/消息行动项线索 |
| `action.source` | URL/ID/更新时间 | message ID/thread ID | message ID/conversation ID |
| `risk` | 项目风险字段（如有） | 客户延迟/变更线索 | 内部阻塞线索 |
| `document` | 文件 ID/链接（如有） | 附件 ID/文件名 | 钉盘/消息附件 ID（如有） |

## 第二阶段：受控写回（仅在验收后）

1. PM 在 Harness 中审阅结构化行动项和日期影响。
2. Harness 生成变更预览：目标系统、记录 ID、旧值、新值、来源、原因。
3. PM 明确确认后，才调用自研项目系统的写回接口。
4. 将请求 ID、响应、操作者、时间和最终版本记录在审计日志。

阿里邮箱和钉钉的发送/发帖功能应排在项目系统受控写回之后；高风险沟通始终保持 PM 审阅。

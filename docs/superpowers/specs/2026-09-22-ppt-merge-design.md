# PPT 合并功能设计（IP266 项目进展汇报）

日期：2026-09-22
状态：已实现并验证（2026-10-09 用 IP266 真实数据完成端到端测试：Scan 排除 00-SUM、每部门取最新、4 部门合并 12 页、封面占位替换、源格式保留均通过）

## 背景

各部门把进展 PPT 更新在 `05-项目进展汇报\01-RD … 12-RA` 各部门文件夹下。PM 的工作流程是：查看近几天哪些部门更新了 PPT → 把这些 PPT 汇总成一份完整 PPT → 邮件发给客户。本设计将"汇总合并"环节自动化。邮件环节本次不做（PM 人工检查合并结果后自行发送）。

## 需求（已与 PM 确认）

| 决策点 | 结论 |
|---|---|
| 候选选择 | 自动拉取近 N 天修改的 PPT 进清单；**每个部门只取修改时间最新的一份**（同部门多份为迭代版本，取最新，避免重复内容） |
| 页范围 | 每份 PPT **保留首页作部门分隔页**（首页天然带部门名）、只去末页（2026-10-09 按 PM 反馈调整，原为去首尾页） |
| 合并顺序 | 按部门文件夹编号升序（01→12）；同部门按文件修改时间升序 |
| 样式 | 保留各 PPT 源格式（部门模板不同，不做主题统一） |
| 首尾页 | 使用 `05-项目进展汇报\PPT模板.pptx`：封面取模板第 4 页（替换 `IPXXXX`→项目号、`202X.XX.XX`→汇报日期，均为规整文本框），尾页取模板第 23 页（"感谢您的聆听!"，直接使用）；各部门 PPT 自身的首尾页仍去除 |
| 输出 | `05-项目进展汇报\00-SUM\IP266-项目进展汇报-合并-<yyyy.M.d>.pptx`；已存在时先确认再覆盖 |
| 调用方式 | 对话指令 + 确认流（与文件加密功能一致），不做 UI |
| 邮件 | 不在本次范围 |

## 架构

复制文件加密功能的模式：**脚本承载核心逻辑，Agent 负责对话编排**。

### 组件 1：`pm-workbench\merge-ppt.ps1`

参数化脚本，两个动作：

- `-Scan -Project <ID> [-Days <N>]`：扫描 `01-Project-Ongoing\<ID>\05-项目进展汇报\` 下 `01-*` 到 `12-*` 的部门文件夹（**排除 00-SUM**，它是输出目录），找出修改时间在近 N 天内的 `.pptx`（不认 .ppt/.pdf）。**每个部门文件夹只保留修改时间最新的一份**（同部门其余为历史版本，舍去）。输出 JSON 清单：路径、部门文件夹名、修改时间、页数、同部门被舍弃的旧版本清单（供 Agent 展示参考）。
- `-Merge -Project <ID> -List <json清单文件> [-OutputPath <路径>] [-Date <汇报日期>]`：合并流程为——复制模板 → 取第 4 页作封面（替换 `IPXXXX`→项目号、`202X.XX.XX`→汇报日期，缺省当天）→ 删除模板其余页 → 按清单顺序 `Slides.InsertFromFile(文件, 位置, 2, 页数-1)` 插入各部门第 2 页至倒数第 2 页（去首尾页，保留源格式）→ 模板第 23 页自然成为尾页。页数 < 3 的文件跳过并记录警告。返回结果摘要（合并文件数、每份取页范围、总页数、跳过清单）。

### 组件 2：对话流程（Agent 按 system-prompt 规则执行）

1. PM 说"合并近 N 天的 PPT"（N 缺省 3）；
2. Agent 调 `-Scan`，以表格呈现候选（部门 / 文件名 / 修改时间 / 页数），请 PM 确认或剔除；
3. PM 确认后 Agent 调 `-Merge`；
4. Agent 报告输出路径与合并摘要，提醒 PM 打开检查后自行发邮件。

### 组件 3：规则沉淀

- `preset/system-prompt.md` 增加"PPT 合并约定"条目（与文件加密约定并列）；
- `workflows/weekly-review.md` 关联说明（周报流程会用到合并结果）。

## 边界与错误处理

- 文件被占用（他人正在编辑）：跳过该文件并在结果中报告，不中断整体合并；
- 部门近 N 天更新多份：**每个部门只取最新一份**（自动去重），同部门旧版本在候选清单中展示为"已舍弃的旧版本"供 PM 核对，PM 仍可在确认环节剔除个别部门；
- 扫描结果为空：报告"近 N 天无更新"，不生成文件；
- COM 绑定 WPS（本机现状）：实现时验证 `InsertFromFile` 在 WPS 下是否保留源格式；不行则退级为"打开源文件→复制页范围→`ppPasteKeepSourceFormatting` 粘贴"，对外行为不变；
- Office 环境差异：脚本只使用 2007–2019 通用 COM 接口（与 encrypt-office.ps1 同样的兼容原则）。

## 测试

1. 单元验证：`-Scan` 对真实目录返回正确清单（验证排除 00-SUM、N 天过滤）；
2. 合并验证：用 2–3 份真实 PPT 合并，检查封面（项目号/日期已替换）、页序、各部门首尾页已去、源格式保留、尾页、输出命名；
3. 异常验证：锁定文件跳过、少于 3 页跳过、覆盖前确认。

## 已知限制

- 首页/末页按"第 1 页/最后一页"字面理解，不识别"封面版式"语义；
- 封面日期缺省为合并执行日，PM 可在确认环节指定其他汇报日期；
- 模板使用 Montserrat、Poppins Black、思源黑体等字体，查看方机器未安装时会有字体替换（模板固有，与合并功能无关）；
- 分节、超链接、动画在合并后可能出现引用错位，属 PowerPoint 合并的固有行为，PM 发送前需人工过一遍。
